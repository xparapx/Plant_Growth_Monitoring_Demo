0개요 & 준비물

7노드 전체를 세우기 전에, 3대로 전 구간을 한 번 관통시킵니다. 여기가 통과하면 나머지는 복사 작업입니다.

데모(0주)의 임무 — 식물은 없습니다 하드웨어와 소프트웨어의 루프가 제대로 도는가를 확인하는 것이 전부입니다. 씨앗도, 처리도, 실험도 아직 없습니다. 흙만 담은 화분 1개로 합니다.

그런데 그 과정에서 파종 전에 반드시 알아야 할 값들이 함께 나옵니다 — 센서 보정, 포화점, 그리고 주기(→ 화분 크기). 데모가 곧 예비실험입니다.

왜 3대인가

노드 7대를 한꺼번에 세우면 문제가 생겼을 때 원인이 노드인지 브로커인지 카메라인지 구분이 안 됩니다. 최소 구성으로 센서 → MQTT → DB → 화면과 급수 폐루프를 각각 한 번씩 끝까지 통과시켜 놓으면, 이후 노드 추가는 펌웨어 복사 + 전원 꽂기가 전부입니다.

데모에서 답이 나오는 것 / 안 나오는 것 나오는 것: 핀 대응, 펌프 실제 전류, 아날로그 전압, 폐루프 동작, 급수 검증 실패 감지, 5분 버킷 정합, 재부팅 복구, 픽셀→cm² 환산
안 나오는 것: 6칸 위치 무관성(프레임 필요), 7노드 동시 부하, 조도 균일도, 열화상 정합 — 전부 2단계로 미룹니다

1브로커 — PC로 먼저

Pi를 기다릴 필요가 없습니다. Pi가 꼭 필요한 건 카메라뿐이고, 브로커·hub.py·대시보드는 전부 PC에서 돕니다.

파이프라인의 80%를 오늘 끝낼 수 있습니다 mosquitto·hub.py·dashboard.py는 플랫폼 무관입니다. PC에서 완성해두면 Pi 도착 시 파일 복사 + 노드의 BROKER IP 한 줄 교체가 이관의 전부입니다.

1) mosquitto 설치

mosquitto.org/download에서 Windows 설치본을 받아 설치합니다.

2) 설정 파일 — PowerShell로 만드세요

C:\Program Files\mosquitto\는 보호된 폴더라 메모장으로 저장하면 권한 거부가 나고, 저장돼도 plant.conf.txt처럼 확장자가 몰래 붙습니다. 관리자 PowerShell에서 만드는 게 확실합니다.

관리자 PowerShell — 권한·확장자 문제 없이 
Set-Content -Path "C:\Program Files\mosquitto\plant.conf" -Encoding ascii -Value @(
  "listener 1883 0.0.0.0",
  "allow_anonymous true"
)
왜 메모장이 아니라 이 방법인가 -Encoding ascii가 한글/BOM 문제를 막고, 확장자가 .conf 그대로 저장됩니다. 메모장으로 하려면 저장 시 파일 형식을 "모든 파일"로 바꾸고 이름을 "plant.conf"(따옴표 포함)로 써야 합니다. 설정 파일에는 한글을 넣지 마세요 — 인코딩이 깨져 mosquitto가 뜨지 않습니다.

3) 브로커가 이미 돌고 있는지 확인 ★

Windows 설치본은 mosquitto를 서비스로 자동 등록해 부팅 때부터 켜두는 경우가 많습니다. 그러면 따로 실행할 필요 없이 이미 브로커가 살아 있습니다.

PowerShell 
Get-Service mosquitto
결과뜻 · 다음
Running이미 브로커가 돎. 4)의 실행을 건너뛰고 바로 테스트로.
단 기본 설정(localhost 전용)이라 같은 PC 테스트만 됨 — 데모엔 충분
Stopped / 없음4)에서 수동으로 띄움
데모는 이대로 충분합니다 — 노드 붙일 때만 손보면 됩니다 서비스는 plant.conf가 아니라 기본 설정으로 돌아 외부(WiFi) 접속이 막혀 있습니다. 지금은 PC 하나로 하는 테스트라 문제없습니다. 실제 노드를 붙이는 단계에서만 net stop mosquitto로 끄고 아래 4)처럼 plant.conf로 다시 띄우면 됩니다.

4) (Stopped일 때만) 방화벽 열기 · 수동 실행

3)이 Running이면 이 단계는 건너뛰세요. Stopped이거나 plant.conf로 다시 띄워야 할 때만 합니다.

관리자 PowerShell — 이 창은 켜둔 채로 
New-NetFirewallRule -DisplayName "MQTT 1883" -Direction Inbound `
  -Protocol TCP -LocalPort 1883 -Action Allow

cd "C:\Program Files\mosquitto"
.\mosquitto.exe -c plant.conf -v      # -v : 오가는 메시지가 콘솔에 그대로 보임

.\은 "현재 폴더의 이 파일"이라 PATH와 무관하게 실행됩니다. 이 창을 닫으면 브로커가 꺼집니다.

방화벽이 1순위 실패 원인입니다 노드가 rc=-2로 계속 실패하는데 PC 자체 테스트는 되는 경우 — 거의 항상 방화벽입니다. 공용 네트워크 프로파일에서 특히 잘 막힙니다.

5) 브로커 주소 확인 ★

PowerShell 
ipconfig

IPv4 주소(예: 192.168.0.15)가 노드 펌웨어의 BROKER 값이 됩니다.

1) OS · 접속

Raspberry Pi Imager로 Raspberry Pi OS (64-bit, Bookworm) Desktop을 굽습니다. 고급 설정(톱니바퀴)에서 호스트명 planthub, SSH 사용, WiFi, 국가 KR을 미리 넣으면 모니터 없이 접속됩니다.

Lite 아님 — Desktop picamera2와 카메라 스택이 기본 포함되어 있어 설치 사고가 줄어듭니다.
PC 터미널 
ssh pi@planthub.local

# Pi 안에서
sudo apt update && sudo apt full-upgrade -y
hostname -I          # ← 이 IP가 새 BROKER 주소

2) mosquitto

Pi 
sudo apt install -y mosquitto mosquitto-clients

sudo tee /etc/mosquitto/conf.d/plant.conf > /dev/null << 'EOF'
listener 1883 0.0.0.0
allow_anonymous true
EOF
sudo systemctl restart mosquitto
systemctl status mosquitto      # active (running) 확인 → q

apt로 설치하면 부팅 시 자동 실행까지 자동으로 등록됩니다.

IP를 고정하세요 공유기 관리페이지에서 DHCP 예약으로 Pi의 IP를 묶어두세요. 재부팅 때 IP가 바뀌면 노드 7대의 펌웨어를 전부 다시 올려야 합니다.

연결 자체 테스트 — 새 창 2개

브로커가 살아 있으니(3·4단계), 새 창 2개를 열어 메시지가 오가는지 봅니다. PATH 등록은 필요 없습니다 — 아래처럼 전체 경로로 바로 실행하면 됩니다.

새 창 A — 구독 (결과가 여기 뜸) 
& "C:\Program Files\mosquitto\mosquitto_sub.exe" -h localhost -t 'plant/#' -v

실행하면 아무것도 안 뜨고 커서만 깜빡입니다 — 정상입니다. 메시지를 기다리는 중입니다. 이 창은 그대로 둡니다.

새 창 B — 발행 
& "C:\Program Files\mosquitto\mosquitto_pub.exe" -h localhost -t 'plant/test' -m '{\"hello\":1}'

창 A에 plant/test {\"hello\":1}이 뜨면 브로커 정상입니다.

⚠ JSON 안의 큰따옴표는 \"로 이스케이프 PowerShell은 작은따옴표 안이라도 큰따옴표를 벗겨서 전달합니다. -m '{\"hello\":1}'처럼 백슬래시를 붙이지 않으면 깨진 JSON이 전송되어 hub.py가 파싱하다 오류납니다.
이게 번거로우면 아래 MQTT Explorer를 쓰세요 — GUI에 원본 그대로 붙여넣으면 됩니다.
전체 경로가 번거로우면 — PATH 등록 (선택) 매번 & "C:\..."를 치기 싫으면 한 번만 등록하면 이름(mosquitto_sub)으로 됩니다. 관리자 권한이 없으면 "Machine" 대신 "User"를 쓰세요 (레지스트리 오류 방지). 
[Environment]::SetEnvironmentVariable("Path",
  $env:Path + ";C:\Program Files\mosquitto", "User")
등록 후 창을 완전히 닫고 새로 열어야 반영됩니다. 새 창에서 mosquitto_sub --help가 뜨면 성공. 단 JSON 이스케이프(\")는 PATH와 무관하게 여전히 필요합니다.

plant/hub.py 
"""
Plant Hub -- MQTT subscriber + SQLite writer   (runs on PC or Pi, unchanged)

subscribe : plant/+/env    -> readings   (5-min bucket, ONE env node = the box)
            plant/+/soil   -> soil       (5-min bucket, one row PER PLANT)
            plant/+/pump   -> pump_log   (event: irrigation record)
            plant/+/growth -> growth     (daily, one row PER PLANT)
store     : SQLite (plant.db) -- single source of truth
time      : ts is UTC.  +9h KST applied only at display/analysis time.
"""
import json, sqlite3, signal, sys
import paho.mqtt.client as mqtt

BROKER = "localhost"
PORT   = 1883
DB     = "plant.db"

sys.stdout.reconfigure(line_buffering=True)

conn = sqlite3.connect(DB, check_same_thread=False)

# environment = the whole grow box.  ONE node.  no soil here.
conn.execute("""
CREATE TABLE IF NOT EXISTS readings(
  id   INTEGER PRIMARY KEY AUTOINCREMENT,
  ts   TEXT DEFAULT CURRENT_TIMESTAMP,
  node TEXT,
  temp  REAL,     -- C    (BME688 = representative)
  hum   REAL,     -- %    (BME688)
  press REAL,     -- hPa  (BME688)
  vpd   REAL,     -- kPa  <- drives transpiration => drying rate => cycle period
  lux   REAL,     -- lx   (proxy only, NOT PAR -- see FAQ)
  co2   REAL,     -- ppm  (SCD41)
  n     INTEGER   -- samples in bucket (quality indicator)
)""")

# soil = per pot.  one watering node per plant.
conn.execute("""
CREATE TABLE IF NOT EXISTS soil(
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  ts       TEXT DEFAULT CURRENT_TIMESTAMP,
  node     TEXT,
  plant_id TEXT,   -- p1..p6
  treat    TEXT,   -- A (well-watered) | B (deficit)
  pct      REAL,
  n        INTEGER
)""")

conn.execute("""
CREATE TABLE IF NOT EXISTS pump_log(
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  ts          TEXT DEFAULT CURRENT_TIMESTAMP,
  node        TEXT,
  plant_id    TEXT,
  treat       TEXT,
  dur_ms      INTEGER,
  soil_before REAL,
  soil_after  REAL,
  reason      TEXT    -- filled | verify_fail | manual
)""")

conn.execute("""
CREATE TABLE IF NOT EXISTS growth(
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  ts        TEXT DEFAULT CURRENT_TIMESTAMP,
  plant_id  TEXT,
  treat     TEXT,
  area_cm2  REAL,     -- projected canopy area (NOT leaf area -- see FAQ)
  area_px   INTEGER,
  px_per_cm REAL,     -- scale at capture (traceability + rig-moved alarm)
  ok        INTEGER
)""")
conn.commit()

def ins(table, d, cols):
    vals = [d.get(c) for c in cols]
    t = d.get("t")
    ph = ",".join(["?"] * len(cols))
    if t:
        conn.execute(f"INSERT INTO {table}(ts,{','.join(cols)}) VALUES(?,{ph})",
                     (t, *vals))
    else:
        conn.execute(f"INSERT INTO {table}({','.join(cols)}) VALUES({ph})", vals)
    conn.commit()

def on_connect(c, u, f, rc, props):
    print(f"broker connect: {rc}")
    for t in ("plant/+/env", "plant/+/soil", "plant/+/pump", "plant/+/growth"):
        c.subscribe(t)

def on_message(c, u, msg):
    try:
        d = json.loads(msg.payload.decode())
    except Exception as e:
        print(f"parse failed: {e}")
        return

    if msg.topic.endswith("/env"):
        ins("readings", d, ["node", "temp", "hum", "press", "vpd", "lux", "co2", "n"])
        print(f"env  : {d}")

    elif msg.topic.endswith("/soil"):
        ins("soil", d, ["node", "plant_id", "treat", "pct", "n"])
        print(f"soil : {d}")

    elif msg.topic.endswith("/pump"):
        ins("pump_log", d, ["node", "plant_id", "treat", "dur_ms",
                            "soil_before", "soil_after", "reason"])
        flag = "  <<< CHECK TUBE/RESERVOIR" if d.get("reason") == "verify_fail" else ""
        print(f"pump : {d}{flag}")

    elif msg.topic.endswith("/growth"):
        # one photo -> many plants: expand list into one row per plant
        for p in d.get("plants", []):
            p["t"] = d.get("t")
            ins("growth", p,
                ["plant_id", "treat", "area_cm2", "area_px", "px_per_cm", "ok"])
        print(f"growth: {len(d.get('plants', []))} plants")

def shutdown(signum, frame):
    print("shutting down...")
    try: client.disconnect()
    except Exception: pass
    try: conn.close()
    except Exception: pass
    sys.exit(0)

signal.signal(signal.SIGTERM, shutdown)
signal.signal(signal.SIGINT,  shutdown)

client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)
client.on_connect = on_connect
client.on_message = on_message
client.connect(BROKER, PORT, keepalive=60)
client.loop_forever()

★ 왜 R4 + Base Shield인가 — 허브가 필요 없습니다 Core S3는 I2C 포트(Port A)가 1개뿐이라 센서 3~4개를 물리려면 허브가 필요했습니다. Base Shield V2는 I2C 포트가 4개라, 센서를 포트마다 하나씩 꽂으면 끝입니다 — 허브도, 데이지체인도, 멀티플렉서도 불필요합니다.

I2C는 원래 버스라 4개 포트가 전기적으로 같은 SDA/SCL에 묶여 있습니다. 주소가 전부 달라(0x76 / 0x62 / 0x23 / 0x33) 한 버스에 매달려도 서로 안 헷갈립니다.
⚠️ Base Shield 전원 스위치를 5V로 Base Shield V2에는 5V / 3.3V 토글 스위치가 있습니다. UNO R4와 M5 센서는 5V이므로 반드시 5V 위치로 두세요. 3.3V로 두면 센서가 인식되지 않거나 값이 튑니다.
막힐 때 — 한 번에 하나씩 네 센서를 한꺼번에 꽂았는데 i2c_scan에 일부만 잡히면, 하나씩만 꽂아 각각 확인하세요. 케이블·접촉 문제인지 특정 센서 문제인지 즉시 갈립니다.

센서 배치 — 값을 망치는 자리

  • CO₂(SCD4x): 통풍구를 막지 말 것. 케이스에 넣으면 구멍 필수
  • 조도: 잎과 같은 높이·같은 방향(위를 보게). 그늘에 두면 식물이 받는 빛과 무관한 값
  • R4 + Shield 본체: 물 튀는 곳 위쪽 금지. 케이스 권장
온습도 대표값은 BME688 — SCD41 값은 쓰지 마세요 두 센서 모두 온습도를 내놓지만 평균 내면 안 됩니다. 계통오차라 평균으로 안 사라집니다. 하나를 대표로 정하고 나머지는 버립니다.

BME688을 대표로 씁니다 — SCD41은 자체 발열로 1~3°C 높게 나오는 알려진 특성이 있고, BME688은 기압까지 주어 VPD를 제대로 계산할 수 있기 때문입니다. SCD41의 온습도는 자기 CO₂ 보정에만 내부적으로 쓰이게 두면 됩니다.
★ 왜 습도가 아니라 VPD인가 — 이 실험에서 중요합니다 식물이 물을 얼마나 빨리 뽑아 쓰는지는 습도(%)가 아니라 VPD(수증기압 결손)가 정합니다. 같은 60% RH여도 20°C와 30°C에서 증산량이 2배 가까이 다릅니다.

VPD가 곧 마르는 속도 → 톱니의 주기입니다. 그러니 "환경이 같았다"를 증명할 때 RH가 아니라 VPD를 보고해야 합니다.
VPD = 0.6108 · exp(17.27T/(T+237.3)) · (1 − RH/100) [kPa]
⚠️ BME688의 가스 히터는 끄고 씁니다 BME688은 VOC를 재려고 내부 열판을 300°C 넘게 가열합니다. 그러면 자기 온습도가 오염됩니다.
그리고 가스값은 보정 안 된 저항값이라 어떤 물질인지 알 수 없고, 습도·온도에 심하게 흔들립니다. 이 실험에서 검정할 수 있는 게 없습니다. → setGasHeater(0, 0)으로 끄세요.

정말 VOC를 보고 싶다면 켜도 됩니다. 대신 온도가 1~2°C 뜨는데, 여섯 화분 모두에 똑같이 적용되므로 그룹 비교는 안 깨집니다. 절대값 보고만 주의하세요.

env_sensor_test.ino — 값 확인 (SCD4x 신버전 API) 
#include <Wire.h>
#include <Adafruit_BME680.h>
#include <SensirionI2cScd4x.h>          // ★ 신버전: I2c 소문자
#include <BH1750.h>

#ifdef NO_ERROR
#undef NO_ERROR
#endif
#define NO_ERROR 0

const uint16_t ALTITUDE_M = 40;         // ★ 학교 해발고도(m)
const uint8_t  SCD41_ADDR = 0x62;

Adafruit_BME680   bme;
SensirionI2cScd4x scd4x;
BH1750            lightMeter;
bool bmeOK=false, scdOK=false, luxOK=false;

float esat(float t){ return 0.6108f*expf(17.27f*t/(t+237.3f)); }
float vpdOf(float t,float rh){ return esat(t)*(1.0f-rh/100.0f); }

void setup(){
  Serial.begin(115200);
  while(!Serial && millis()<3000){}
  Wire.begin();
  delay(200);

  bmeOK = bme.begin(0x76) || bme.begin(0x77);
  if(bmeOK){
    bme.setTemperatureOversampling(BME680_OS_8X);
    bme.setHumidityOversampling(BME680_OS_2X);
    bme.setPressureOversampling(BME680_OS_4X);
    bme.setIIRFilterSize(BME680_FILTER_SIZE_3);
    bme.setGasHeater(0,0);              // 가스히터 OFF
  }
  Serial.println(bmeOK?"BME688 OK":"BME688 FAIL");

  scd4x.begin(Wire, SCD41_ADDR);        // ★ 신버전: 주소 인자
  scd4x.stopPeriodicMeasurement(); delay(500);
  scd4x.setSensorAltitude(ALTITUDE_M);
  scdOK = (scd4x.startPeriodicMeasurement()==NO_ERROR);
  Serial.println(scdOK?"SCD41 OK (첫 값 ~5초)":"SCD41 FAIL");

  luxOK = lightMeter.begin(BH1750::CONTINUOUS_HIGH_RES_MODE);
  Serial.println(luxOK?"DLight OK":"DLight FAIL");
}

void loop(){
  float t=NAN,hm=NAN,pr=NAN,vpd=NAN,lx=NAN; uint16_t co2=0;

  if(bmeOK && bme.performReading()){
    t=bme.temperature; hm=bme.humidity; pr=bme.pressure/100.0f; vpd=vpdOf(t,hm);
  }
  bool ready=false;
  if(scdOK && scd4x.getDataReadyStatus(ready)==NO_ERROR && ready){   // ★ 신버전 함수명
    float st,sh; scd4x.readMeasurement(co2, st, sh);   // 온습도는 버림 (CO2만)
  }
  if(luxOK) lx=lightMeter.readLightLevel();

  Serial.print("T=");   if(!isnan(t))  Serial.print(t,1);  else Serial.print("--");
  Serial.print("C RH=");if(!isnan(hm)) Serial.print(hm,1); else Serial.print("--");
  Serial.print("% P="); if(!isnan(pr)) Serial.print(pr,1); else Serial.print("--");
  Serial.print("hPa VPD=");if(!isnan(vpd))Serial.print(vpd,2);else Serial.print("--");
  Serial.print("kPa CO2=");if(co2)      Serial.print(co2);  else Serial.print("--");
  Serial.print("ppm Lux=");if(!isnan(lx))Serial.print(lx,0);else Serial.print("--");
  Serial.println();
  delay(2000);
}

 * ═══════════════════════════════════════════════════════════
 *  식물 생장 모니터링 — 환경 노드 (Arduino UNO R4 WiFi)   [데모판]
 *
 *  Grove Base Shield V2 — I2C 포트 4개. 허브 없이 하나씩 꽂음
 *    BME688  0x76 : 온도·습도·기압  <- 대표값. 가스히터 OFF. VPD 계산
 *    SCD41   0x62 : CO2 전용 (내장 온습도는 사용하지 않음)
 *    DLight  0x23 : 조도 (lux)
 *    MLX90640 0x33: 2단계
 *  Base Shield 전원 스위치는 반드시 5V 위치.
 *
 *  전송 : plant/<nodeId>/env    NTP(UTC) 정각 격자 5분 평균
 * ═══════════════════════════════════════════════════════════
 *  ★ Core S3 판과 다른 점 (R4 WiFi 전용)
 *    · M5Unified 없음 → 화면 코드 제거 (R4는 12x8 LED 매트릭스뿐)
 *    · WiFi 라이브러리 = WiFiS3 (ESP32 아님)
 *    · Wire.begin() — 핀 번호 지정 안 함 (SDA/SCL 고정)
 *    · NTP = RTC(WiFiS3 내장) 이용, UTC
 *    · 센서 라이브러리·MQTT·타당성 게이트·평균 로직은 그대로
 *  라이브러리: WiFiS3(보드 내장) / PubSubClient / Sensirion I2C SCD4x(신버전)
 *              Adafruit BME680(BME688 호환) / BH1750
 * ═══════════════════════════════════════════════════════════

#include <PubSubClient.h>
#include <Wire.h>
#include <SensirionI2cScd4x.h>          // 신버전: I2c 소문자

#include <RTC.h>                         // R4 내장 RTC (NTP 시각 보관)

#ifdef NO_ERROR                          // SCD4x 신버전 매크로 충돌 방지
#undef NO_ERROR
#endif
#define NO_ERROR 0
const uint8_t SCD41_ADDR = 0x62;

// ══════════ 사용자 설정 ══════════
const char* WIFI_SSID = "your-hotspot";
const char* WIFI_PASS = "your-password";
const char* BROKER    = "192.168.0.15";     // ★ PC의 IPv4 (ipconfig) → Pi 도착 후 교체
const int   PORT      = 1883;

const uint16_t ALTITUDE_M = 40;             // ★ 학교 해발고도(m) — SCD41 CO2 보정
const int   PUBLISH_MIN = 5;
const unsigned long SAMPLE_MS = 10000;      // 5분에 n≈30
const long  TZ_OFFSET = 0;                  // NTP는 UTC로 저장 (hub에서 +9h)
// ════════════════════════════════

WiFiClient net;
PubSubClient client(net);
SensirionI2cScd4x scd4x;                 // 신버전 클래스명
Adafruit_BME680  bme;
BH1750           lightMeter;

String nodeId, topic;
double sT=0, sH=0, sP=0, sV=0, sL=0, sC=0;
int n=0, nC=0, nB=0;
bool bmeOK=false, scdOK=false, luxOK=false, timeOK=false;
long curBucket = -1;
unsigned long lastSample = 0;
int failStreak = 0;

// ── VPD — 습도가 아니라 이것이 증산을(=마르는 속도를) 정함 ──
float esat(float t)            { return 0.6108f * expf(17.27f*t/(t+237.3f)); }   // kPa
float vpdOf(float t, float rh) { return esat(t) * (1.0f - rh/100.0f); }          // kPa

// R4는 MAC을 WiFi.macAddress()로 얻음 (연결 후)
void makeNodeId() {
  byte mac[6]; WiFi.macAddress(mac);
  char id[16];
  snprintf(id, sizeof(id), "env_%02X%02X%02X", mac[3], mac[4], mac[5]);
  nodeId = String(id);
  topic  = "plant/" + nodeId + "/env";
}

void connectWiFi() {
  if (WiFi.status() == WL_CONNECTED) return;
  Serial.print("WiFi");
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  unsigned long t0 = millis();
  while (WiFi.status() != WL_CONNECTED && millis()-t0 < 15000) { delay(500); Serial.print("."); }
  Serial.println(WiFi.status()==WL_CONNECTED ? " OK" : " FAIL");
}

void connectBroker() {
  int tries = 0;
  while (!client.connected() && tries++ < 5) {
    connectWiFi();
    String cid = nodeId + "-" + String(random(0xffff), HEX);
    Serial.print("MQTT");
    if (client.connect(cid.c_str())) { Serial.println(" OK"); return; }
    Serial.print(" rc="); Serial.println(client.state());   // -2 = 거부/방화벽
    delay(2000);
  }
}

// R4 WiFi는 NTP를 WiFi.getTime()으로 받아 내장 RTC에 심음 (UTC epoch)
void syncTime() {
  Serial.print("NTP");
  unsigned long epoch = 0, t0 = millis();
  while (epoch == 0 && millis()-t0 < 10000) { epoch = WiFi.getTime(); delay(500); Serial.print("."); }
  if (epoch) {
    RTC.begin();
    RTCTime now((time_t)epoch);
    RTC.setTime(now);
    timeOK = true;  Serial.println(" OK");
  } else { timeOK = false; Serial.println(" FAIL -> 정각정렬 없이 동작"); }
}

long nowEpoch() {
  if (!timeOK) return 0;
  RTCTime t; RTC.getTime(t); return (long)t.getUnixTime();
}

String epochToStr(long e) {
  time_t t=(time_t)e; struct tm ti; gmtime_r(&t, &ti);
  char b[32]; strftime(b, sizeof(b), "%Y-%m-%d %H:%M:%S", &ti);
  return String(b);
}

// 얼어붙은 센서가 물리적으로 불가능한 값을 반복하는 고장 모드를 차단
bool plausibleTH(float t, float h) { return t>-10 && t<60 && h>=0 && h<=100; }
bool plausibleCO2(float c)         { return c>300 && c<10000; }

void initSensors() {
  // BME688 — 대표 온습도. 가스히터는 끔(자체 발열로 온습도가 오염됨)
  bmeOK = bme.begin(0x76);
  if (!bmeOK) bmeOK = bme.begin(0x77);          // 보드에 따라 0x77
  if (bmeOK) {
    bme.setTemperatureOversampling(BME680_OS_8X);
    bme.setHumidityOversampling(BME680_OS_2X);
    bme.setPressureOversampling(BME680_OS_4X);
    bme.setIIRFilterSize(BME680_FILTER_SIZE_3);
    bme.setGasHeater(0, 0);                     // ★ OFF — VOC 쓰려면 (320,150)
  }
  Serial.println(bmeOK ? "BME688 시작" : "BME688 실패 - 0x76/0x77 확인");

  scd4x.begin(Wire, SCD41_ADDR);                // 신버전: 주소 인자 필요
  scd4x.stopPeriodicMeasurement(); delay(500);
  scd4x.setSensorAltitude(ALTITUDE_M);          // 기압 보정 (측정 정지 중에만)
  scdOK = (scd4x.startPeriodicMeasurement() == NO_ERROR);
  Serial.println(scdOK ? "SCD41 시작" : "SCD41 실패 - 0x62 확인");

  luxOK = lightMeter.begin(BH1750::CONTINUOUS_HIGH_RES_MODE);
  Serial.println(luxOK ? "DLight 시작" : "DLight 실패 - 0x23 확인");
}

void recoverI2C() {
  Serial.println("[RECOVER] I2C 복구");
  Wire.end(); delay(50);
  Wire.begin();                                 // R4 : 핀 지정 없음
  initSensors();
  failStreak = 0;
  if (!bmeOK && !scdOK && !luxOK) { Serial.println("[RECOVER] 실패 -> 리셋"); NVIC_SystemReset(); }
}

void takeSample() {
  bool any = false;

  // ── BME688 : 대표 온습도 + 기압 -> VPD ──
  if (bmeOK && bme.performReading()) {
    float t = bme.temperature, hm = bme.humidity, pr = bme.pressure / 100.0f;  // Pa -> hPa
    if (plausibleTH(t, hm)) { sT += t; sH += hm; sP += pr; sV += vpdOf(t, hm); nB++; any = true; }
  }

  // ── SCD41 : CO2만 사용 (온습도 t,hm은 읽고 버림) ──
  uint16_t co2=0; float t=0, hm=0; bool ready=false;
  if (scdOK && scd4x.getDataReadyStatus(ready)==NO_ERROR && ready) {   // 신버전 함수명
    if (scd4x.readMeasurement(co2, t, hm)==NO_ERROR && co2!=0 && plausibleCO2(co2)) { sC += co2; nC++; any = true; }
  }

  float lx = luxOK ? lightMeter.readLightLevel() : NAN;
  if (!isnan(lx) && lx >= 0) { sL += lx; any = true; }

  n++;
  if (any) failStreak = 0; else failStreak++;
}

void publishAverage(long bucket) {
  if (n <= 0) return;
  int cb = nB > 0 ? nB : 1;
  int cc = nC > 0 ? nC : 1;
  char p[320];
  String ts = timeOK ? epochToStr(bucket) : String("");
  snprintf(p, sizeof(p),
    "{\"node\":\"%s\",\"t\":\"%s\",\"temp\":%.2f,\"hum\":%.2f,"
    "\"press\":%.1f,\"vpd\":%.3f,\"lux\":%.1f,\"co2\":%.1f,\"n\":%d}",
    nodeId.c_str(), ts.c_str(), sT/cb, sH/cb, sP/cb, sV/cb, sL/n, sC/cc, n);
  client.publish(topic.c_str(), p);
  Serial.print("PUB: "); Serial.println(p);
}

void resetAccum() { sT=sH=sP=sV=sL=sC=0; n=0; nC=0; nB=0; }

void setup() {
  Serial.begin(115200);
  Wire.begin();                            // R4 : Base Shield I2C (SDA/SCL 고정)
  initSensors();

  connectWiFi();
  makeNodeId();
  syncTime();
  client.setServer(BROKER, PORT);
  connectBroker();

  Serial.print("Node : "); Serial.println(nodeId);
  Serial.print("Topic: "); Serial.println(topic);
  if (timeOK) { long s = PUBLISH_MIN*60L; curBucket = (nowEpoch()/s)*s; }
}

void loop() {
  if (!client.connected()) connectBroker();
  client.loop();

  if (failStreak >= FAIL_LIMIT) recoverI2C();

  unsigned long now = millis();
  long s = PUBLISH_MIN * 60L;

  if (timeOK) {
    long bucket = (nowEpoch()/s)*s;
    if (curBucket < 0) curBucket = bucket;
    if (bucket != curBucket) { publishAverage(curBucket); resetAccum(); curBucket = bucket; }
  } else {
    static unsigned long lastPub = 0;
    if (now - lastPub >= (unsigned long)PUBLISH_MIN*60000UL) { lastPub = now; publishAverage(0); resetAccum(); }
  }

  if (now - lastSample >= SAMPLE_MS) { lastSample = now; takeSample(); }
  delay(20);
}

Watering Unit 핀맵(공식): PORT.B — 검정 GND / 빨강 5V / 노랑 PUMP_EN / 흰색 Analog Output. 유닛에 펌프 드라이버가 내장되어 있어 MOSFET·플라이백 다이오드가 필요 없습니다.

유닛 1개 = 포트 1개. 그래서 노드를 나눴습니다 Watering Unit은 제어핀 1 + 아날로그핀 1을 함께 씁니다. 한 보드에 2개를 붙이려면 Port C의 ADC2가 WiFi와 충돌해 아날로그를 못 읽습니다. 노드를 나누면 이 문제가 통째로 사라집니다 — 크로스 분기도 PbHUB도 필요 없습니다.

실측 ② — 아날로그 전압 3.3V 초과? ⚠️

멀티미터로 흰색 선의 전압을 재세요 — 공기 중 / 물속 양쪽 모두.

3.3V를 넘으면 ESP32 ADC가 손상됩니다 유닛은 5V로 구동됩니다. M5Core Basic에는 I/O 라인에 3.3V 클램프 다이오드 어레이가 있다는 포럼 보고가 있으나, Core S3에 동일 보호가 있는지는 확인되지 않았습니다. 3.3V를 넘으면 분압 저항(예: 10k/20k)이 필요합니다. 재보고 넘어가세요.

보정 ① — 마름/젖음 필수

  1. pin_id.ino를 올린 채 시리얼을 봅니다
  2. 공기 중 값 기록 → SOIL_DRY ___
  3. 물에 (전자부품 선까지만) 담근 값 기록 → SOIL_WET ___
  4. 정전용량식은 젖을수록 ADC가 낮아집니다 — DRY > WET이면 정상

보정 ② — DOSE_MS 계량컵

  1. 튜브 끝을 빈 계량컵에 넣습니다 (화분 아님)
  2. pump_burst.ino로 3초 구동 → 나온 물 mL 측정 ___ mL / 3s
  3. 1회 급수 목표(예: 50mL)에 맞춰 DOSE_MS 계산
애매하면 줄이세요 과습이 고사 원인 1위입니다. 물이 모자라면 식물은 시들었다 회복하지만, 뿌리가 잠기면 회복 없이 죽습니다. 모자라면 다음 주기에 또 주면 됩니다.

② 환기·온도 ↑ (전체에 동일하게) — 통제변인은 "특정 값"이 아니라 "그룹 간 동일"이면 됩니다. 재배함 전체를 26°C로 올려도 여섯 화분 모두 26°C이므로 여전히 통제된 것입니다. 바뀌는 건 "26°C 조건에서 수행했다"는 문장 하나뿐
③ 화분 크기 ↓ — 최후의 수단. 아래 경고 참조
❌ 밴드 폭 ↓ — 주기는 짧아지지만 σ가 작아져 목적이 무너짐
⚠️ 작은 화분의 함정 — 검정하려는 기제를 스스로 봉쇄합니다 널뜀군이 뿌리를 더 뻗는 것이 바로 H₂(경화)의 핵심 기제입니다. 화분이 작으면 뻗을 공간이 없습니다.
주기를 맞추려고 화분을 줄이면 검정하려던 기제를 물리적으로 막아놓고 "경화 효과가 없었다"고 결론짓게 됩니다. 틀린 결론입니다. 부득이 줄였다면 "뿌리 제한이 경화 반응을 억제했을 가능성"을 한계로 명시하세요.

전원 — 노드 1개 = 어댑터 1개

Core S3는 USB-C입니다. 배럴잭이 아닙니다. 개발 중엔 PC USB로 시리얼 보며 작업하고, 방치 테스트 때만 5V 2A USB-C 어댑터를 씁니다.

멀티포트 공용 충전기 금지 분산 노드에는 소프트웨어 인터록이 없습니다 — 노드 6대가 서로를 모르므로 동시에 펌프를 돌릴 수 있습니다. 멀티포트 충전기는 총 와트를 나눠 쓰므로 순간 부하에 전압이 주저앉아 연쇄 리셋이 납니다. 노드마다 독립 어댑터 + 독립 콘센트. 노드 간 신호선이 없으니(전부 무선) 접지 공통도 불필요합니다.
멀티탭 — 물이 있는 책상입니다 멀티탭을 물통·화분보다 높은 곳에(벽·선반). 바닥과 책상 아래 금지. 스위치 달린 멀티탭이 위험합니다 — 누가 무심코 끄면 Pi가 하드 다운되고 SD카드가 깨집니다. Pi는 별도 콘센트 + 정품 27W PD로 빼세요.

7급수 노드 — 펌웨어 (폐루프)

이 코드가 곧 처리(treatment) 투입 장치입니다. 규칙 기반 제어를 "데이터 기반의 미완성 버전"으로 여기지 마세요 — 이게 없으면 실험 자체가 성립하지 않습니다.

★ 이 두 줄이 곧 처리 조건입니다 ON_BELOW(바닥)와 OFF_AT(천장) — 6대의 코드가 완전히 같고 이 두 줄만 다릅니다. 제어 알고리즘 자체가 교락되지 않는다는 뜻입니다.

펌프는 위로만 밀어올립니다. 내려가는 건 식물의 증산·증발이 합니다. 즉 펌프는 진폭을 만드는 게 아니라 가둡니다 — 우리가 정하는 건 "얼마나 마르도록 내버려 둘 것인가"입니다. 자세한 배경은 패널 ★·設.

unsigned long tMark = 0;
float    before = 0, lastSoil = 0;
int      nToday = 0;
int      curDay = -1;
bool     armed = true;

void makeNodeId() {
  byte mac[6]; WiFi.macAddress(mac);
  char id[16];
  snprintf(id, sizeof(id), "wtr_%02X%02X%02X", mac[3], mac[4], mac[5]);
  nodeId = String(id);
  tSoil  = "plant/" + nodeId + "/soil";
  tPump  = "plant/" + nodeId + "/pump";
}

void connectWiFi() {
  if (WiFi.status() == WL_CONNECTED) return;
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  unsigned long t0 = millis();
  while (WiFi.status() != WL_CONNECTED && millis() - t0 < 15000) delay(500);
}

void connectBroker() {
  int tries = 0;
  while (!client.connected() && tries++ < 3) {     // 3회만 — 급수를 막지 않도록
    connectWiFi();
    String cid = nodeId + "-" + String(random(0xffff), HEX);
    if (client.connect(cid.c_str())) { Serial.println("MQTT OK"); return; }
    Serial.print("MQTT rc="); Serial.println(client.state());
    delay(1000);
  }
}

void syncTime() {
  configTime(0, 0, "pool.ntp.org", "time.google.com");
  struct tm ti;
  unsigned long t0 = millis();
  while (!getLocalTime(&ti, 500) && millis() - t0 < 10000) delay(100);
  timeOK = getLocalTime(&ti, 500);
  Serial.println(timeOK ? "NTP OK" : "NTP FAIL");
}

long nowEpoch() { time_t t; time(&t); return (long)t; }

String epochToStr(long e) {
  time_t t = (time_t)e; struct tm ti; gmtime_r(&t, &ti);
  char b[32]; strftime(b, sizeof(b), "%Y-%m-%d %H:%M:%S", &ti);
  return String(b);
}

// 정전용량식: 젖을수록 ADC가 낮아짐 -> 반전 매핑
float soilPct(int raw) {
  float p = (float)(SOIL_DRY - raw) * 100.0f / (float)(SOIL_DRY - SOIL_WET);
  if (p < 0) p = 0;
  if (p > 100) p = 100;
  return p;
}

void publishPump(float aft, const char* reason) {
  char p[288];
  String ts = timeOK ? epochToStr(nowEpoch()) : String("");
  snprintf(p, sizeof(p),
    "{\"node\":\"%s\",\"plant_id\":\"%s\",\"treat\":\"%s\",\"t\":\"%s\","
    "\"dur_ms\":%lu,\"soil_before\":%.1f,\"soil_after\":%.1f,\"reason\":\"%s\"}",
    nodeId.c_str(), PLANT_ID, TREAT, ts.c_str(),
    (unsigned long)nFill * DOSE_MS, before, aft, reason);   // 채움 1회 총 급수시간
  client.publish(tPump.c_str(), p, true);   // retained: 마지막 급수 상태 보존
  Serial.print("PUMP: "); Serial.println(p);
}

// 하루 경계 (UTC 기준 — DB와 일치)
void rollDay() {
  if (!timeOK) return;
  int d = (int)(nowEpoch() / 86400L);
  if (d != curDay) { curDay = d; nToday = 0; }
}

void startDose(unsigned long now) {
  nToday++; nFill++;
  digitalWrite(PIN_PUMP, HIGH); tMark = now; st = 1;
}

void pumpTick(float soil) {
  unsigned long now = millis();
  lastSoil = soil;
  switch (st) {
    case 0:                                        // DRYING — 마르길 기다림
      if (!armed || nToday >= DAILY_MAX) break;
      if (soil < ON_BELOW) {
        before = soil; nFill = 0; startDose(now);
        Serial.printf("[fill] soil %.1f%% < %.1f%% -> 목표 %.1f%%\n",
                      soil, ON_BELOW, OFF_AT);
      }
      break;

    case 1:                                        // DOSING
      if (now - tMark >= DOSE_MS) {
        digitalWrite(PIN_PUMP, LOW); tMark = now; st = 2;
      }
      break;

    case 2:                                        // SOAKING -> 판정
      if (now - tMark < SOAK_MS) break;

      if (soil - before < MIN_RISE) {              // 튜브 빠짐/물통 빔/펌프 고장
        armed = false;
        Serial.printf("[!!] VERIFY FAIL %.1f -> %.1f -- 무장해제\n", before, soil);
        publishPump(soil, "verify_fail");
        st = 0; break;
      }

      if (soil < OFF_AT && nFill < MAX_DOSE_PER_FILL) {
        before = soil; startDose(now);             // ★ 목표까지 반복
        Serial.printf("[dose %d] %.1f%% -> 계속\n", nFill, soil);
      } else {
        Serial.printf("[done] %.1f%% (급수 %d회) -- 이제 마르게 둠\n", soil, nFill);
        publishPump(soil, "filled");               // ★ 도달 -> 손 떼고 마르게 둠
        st = 0;
      }
      break;
  }
}

void publishSoil(long bucket) {
  if (n <= 0) return;
  char p[224];
  String ts = timeOK ? epochToStr(bucket) : String("");
  snprintf(p, sizeof(p),
    "{\"node\":\"%s\",\"plant_id\":\"%s\",\"treat\":\"%s\",\"t\":\"%s\","
    "\"pct\":%.1f,\"n\":%d}",
    nodeId.c_str(), PLANT_ID, TREAT, ts.c_str(), sSoil / n, n);
  client.publish(tSoil.c_str(), p);
  Serial.print("PUB: "); Serial.println(p);
}

void drawScreen() {
  const char* S[] = {"DRY ", "DOSE", "SOAK"};
  M5.Display.setCursor(0, 0);
  M5.Display.setTextSize(3);
  M5.Display.printf("%s / %s\n\n", PLANT_ID, TREAT);
  M5.Display.printf("%5.1f %%\n\n", lastSoil);
  M5.Display.setTextSize(2);
  M5.Display.printf("band %.0f-%.0f\n", ON_BELOW, OFF_AT);
  M5.Display.printf("%s  today %d\n", S[st], nToday);
  M5.Display.printf("%s %s\n", armed ? "ARMED " : "DISARM",
                    client.connected() ? "MQTT" : "----");
}

void setup() {
  // ★ 무엇보다 먼저 — 부팅 중 펌프가 도는 것을 막음
  pinMode(PIN_PUMP, OUTPUT);
  digitalWrite(PIN_PUMP, LOW);

  auto cfg = M5.config();
  M5.begin(cfg);
  M5.Display.setTextColor(CYAN, BLACK);
  Serial.begin(115200);

  analogReadResolution(12);
  pinMode(PIN_SOIL, INPUT);

  connectWiFi();
  makeNodeId();
  syncTime();
  rollDay();
  client.setServer(BROKER, PORT);
  connectBroker();

  Serial.printf("Node : %s  (%s / %s)\n", nodeId.c_str(), PLANT_ID, TREAT);
  Serial.printf("Band : %.1f - %.1f %%\n", ON_BELOW, OFF_AT);
  if (timeOK) { long s = PUBLISH_MIN * 60L; curBucket = (nowEpoch() / s) * s; }
}

void loop() {
  M5.update();
  // 브로커가 없어도 급수는 계속되어야 함 -> 재연결이 루프를 막지 않게
  if (!client.connected()) {
    static unsigned long lastTry = 0;
    if (millis() - lastTry > 30000) { lastTry = millis(); connectBroker(); }
  }
  client.loop();
  rollDay();

  unsigned long now = millis();
  if (now - lastSample >= SAMPLE_MS) {
    lastSample = now;
    float soil = soilPct(analogRead(PIN_SOIL));
    sSoil += soil; n++;
    pumpTick(soil);                              // 5분 평균이 아니라 현재값으로
    drawScreen();
  }

  long s = PUBLISH_MIN * 60L;
  if (timeOK) {
    long bucket = (nowEpoch() / s) * s;
    if (curBucket < 0) curBucket = bucket;
    if (bucket != curBucket) {
      publishSoil(curBucket); sSoil = 0; n = 0; curBucket = bucket;
    }
  } else {
    static unsigned long lastPub = 0;
    if (now - lastPub >= (unsigned long)PUBLISH_MIN * 60000UL) {
      lastPub = now; publishSoil(0); sSoil = 0; n = 0;
    }
  }
  delay(20);
}

튜브를 빈 컵에 두면 정작 검증할 게 검증되지 않습니다 빈 컵이면 수분 폐루프가 안 닫힙니다 — 물을 줘도 센서값이 안 오르니 무조건 verify_fail입니다. 흙 → 센서 → 펌프 → 흙이 실제로 돌아야 dose → soak → verify가 진짜로 시험됩니다. 화분에 흙만 담고 씨앗은 넣지 마세요. 데모 단계에는 식물이 없어야 합니다 — 지금 확인할 것은 루프가 도는가뿐입니다.
  • 흙을 말려 ON_BELOW 아래로 → 펌프 작동, 화면 DOSE
  • 20분 후 SOAK → 목표 미달이면 다시 DOSE → 도달하면 DRY, pump_log에 filled 1행
  • ★ 급수 직후 튜브를 물통에서 빼고 다시 유도 → verify_fail + 화면 DISARM
  • 재부팅 → 펌프 안 돌고 정상 시작 (10k 풀다운 확인)
  • 브로커를 끄고 방치 → 급수는 계속됨, 켜면 재연결
  • ★ 며칠 방치 → 톱니가 반복되는가 · pump_log에서 주기 확인 (패널 6)
  • ★ 로그에서 평균과 σ가 계산되는가 — SELECT AVG(pct), COUNT(*) FROM soil;
SOAK 중 5분 발행이 계속되는지 보세요 상태기계가 제대로 짜였다면 20분 대기 중에도 PUB: {...soil...}이 4번 나옵니다. 멈춘다면 어딘가에서 블로킹하고 있는 것이고, 그러면 verify가 항상 실패합니다.

"""
leafcv -- PROJECTED CANOPY AREA from a top-view image.

NOTE ON NAMING
  This is NOT leaf area.  Overlapping leaves are counted once, so it always
  under-reads true leaf area.  It is a monotonic growth proxy -- enough for
  growth-RATE comparison, but report it as projected canopy area.
"""
import json
import cv2
import numpy as np

CFG = json.load(open("config.json"))

def find_scale(img):
    """px per cm from the ArUco marker, or None."""
    d = cv2.aruco.getPredefinedDictionary(cv2.aruco.DICT_4X4_50)
    det = cv2.aruco.ArucoDetector(d, cv2.aruco.DetectorParameters())
    corners, ids, _ = det.detectMarkers(img)
    if ids is None or len(corners) == 0:
        return None
    c = corners[0].reshape(4, 2)
    sides = [np.linalg.norm(c[i] - c[(i + 1) % 4]) for i in range(4)]
    return (float(np.mean(sides)) / CFG["marker_mm"]) * 10.0

def leaf_mask(bgr):
    b, g, r = cv2.split(bgr.astype(np.float32))
    exg = 2.0 * g - r - b                       # excess green index
    exg = cv2.normalize(exg, None, 0, 255, cv2.NORM_MINMAX).astype(np.uint8)
    exg = cv2.GaussianBlur(exg, (5, 5), 0)
    _, m = cv2.threshold(exg, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)

    k = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    m = cv2.morphologyEx(m, cv2.MORPH_OPEN,  k, iterations=1)   # drop specks
    m = cv2.morphologyEx(m, cv2.MORPH_CLOSE, k, iterations=2)   # fill holes

    # keep only the largest blob = the plant.  kills stray green pixels.
    nlab, lab, stats, _ = cv2.connectedComponentsWithStats(m, 8)
    if nlab <= 1:
        return np.zeros_like(m), 0
    big = 1 + int(np.argmax(stats[1:, cv2.CC_STAT_AREA]))
    return np.where(lab == big, 255, 0).astype(np.uint8), int(stats[big, cv2.CC_STAT_AREA])

def measure(img_path, debug_dir=None):
    img = cv2.imread(img_path)
    if img is None:
        raise FileNotFoundError(img_path)
    ppc = find_scale(img)
    if ppc is None:
        print("[WARN] ArUco not found -- area_cm2 will be null")

    out = []
    for roi in CFG["rois"]:
        x, y, w, h = roi["x"], roi["y"], roi["w"], roi["h"]
        crop = img[y:y + h, x:x + w]
        mask, px = leaf_mask(crop)
        cm2 = round(px / (ppc ** 2), 2) if ppc else None
        ok = 1 if (ppc and 0 < px < 0.9 * w * h) else 0   # blob filling ROI = bad crop
        out.append({"plant_id": roi["plant_id"], "treat": roi["treat"],
                    "area_px": px, "area_cm2": cm2,
                    "px_per_cm": round(ppc, 3) if ppc else None, "ok": ok})
        if debug_dir:
            vis = crop.copy()
            cont, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
            cv2.drawContours(vis, cont, -1, (0, 0, 255), 3)
            cv2.putText(vis, f'{roi["plant_id"]} {cm2}cm2', (10, 40),
                        cv2.FONT_HERSHEY_SIMPLEX, 1.2, (0, 255, 255), 3)
            cv2.imwrite(f'{debug_dir}/{roi["plant_id"]}.jpg', vis)
    return out

if __name__ == "__main__":
    import sys, os
    os.makedirs("debug", exist_ok=True)
    for r in measure(sys.argv[1] if len(sys.argv) > 1 else "calib.jpg", "debug"):
        print(r)

① 복리 — 평균이 0인데 반토막

수익률이 +50%, −50%를 번갈아 납니다. 산술평균은 0%, 본전 같아 보입니다.

100만원 → 150만원 → 75만원 → 112.5만원 → 56.25만원 → ...

본전이 아니라 반토막입니다. 2회마다 −25%. 수익률은 곱해지므로 실제로 더해지는 건 로그이고, 로그는 오목합니다.

② 실효값(RMS) — 물리 시간에 이미 배운 것

교류 전류가 +10A와 −10A를 오가면 평균 전류는 0입니다. 그런데 전열기는 뜨겁습니다.

실효값은 옌센 격차를 메우려고 만든 개념입니다 P = I²R이 제곱(볼록)이라 평균 전류로 계산하면 0이 나오지만 실제 발열은 100R입니다. 그래서 "평균 전류" 대신 √(평균 I²) — 실효값을 씁니다.

그리고 f(x)=x²일 때 그 격차는 정확히 E[X²] − (E[X])² = σ² — 분산 그 자체입니다. 근사가 아니라 등식입니다.

③ 내비게이션 — 막히는 길에서 잃는 시간이 더 크다

A 경로는 늘 50km/h. B 경로는 절반 거리를 90km/h, 절반 거리를 10km/h. 속도의 산술평균은 둘 다 50입니다.

T_A = d / 50           = 0.020 d
T_B = (d/2)/90 + (d/2)/10 = 0.056 d      →  B가 2.8배 오래 걸림

시간 = 거리/속도는 볼록이라 흔들리면 커집니다. 90에서 아끼는 시간보다 10에서 잃는 시간이 훨씬 큽니다.

★ 이 예시는 우리 실험과 정확히 같은 함정을 갖고 있습니다 "거리 기준"으로 반반일 때만 성립합니다. 만약 시간 기준으로 반반이라면 (절반의 시간을 90으로, 절반을 10으로) 이동거리는 90t+10t=100t, 총 2t시간 → 평균속도 50으로 A와 똑같습니다.

게다가 B의 실제 평균속도는 50이 아니라 조화평균 18km/h입니다 — 느린 구간에 오래 머물기 때문입니다.
널뛰는 화분이 마른 쪽에 오래 머물러 평균이 40%가 아닌 34.5%가 되는 것과 같은 구조입니다. "어떻게 가중하느냐"가 답을 바꿉니다 — 그래서 우리는 5분마다 로그를 남깁니다. (패널 設)

④ 위험회피 — 보험사가 돈을 버는 이유

효용은 오목합니다 — 100만원 잃는 고통이 100만원 버는 기쁨보다 큽니다. 그래서 기대금액이 같아도(공정한 도박) 사람은 확정된 쪽을 택합니다. 보험사는 기대값 기준으로 손해인 계약을 팔아 돈을 법니다.

맛집도 같은 구조입니다 — 늘 가는 곳은 항상 80점, 새로운 곳은 반반으로 100점 또는 60점. 기대 점수는 똑같이 80점입니다. 그런데 20점 잃는 실망이 20점 얻는 기쁨보다 커서, 평균 만족도는 새로운 곳이 낮습니다.

비교하려면 평균이 같아야 합니다 "새로운 곳은 100점 아니면 40점(평균 70점)"으로 놓으면 이건 옌센 예시가 아닙니다 — 그냥 평균이 낮은 겁니다. 옌센은 평균이 같을 때만 성립하는 비교입니다. 이 조건을 놓치면 전혀 다른 이야기가 됩니다 — 우리 실험이 "두 그룹의 평균 수분을 같게"에 그토록 매달리는 이유가 바로 이것입니다.

사는 사람 (적립식)수량 = 예산 / P볼록이득 — 쌀 때 많이 사짐

그러니 "변동성은 좋다 / 나쁘다"라는 일반 명제는 존재하지 않습니다. 곡선을 봐야만 알 수 있습니다. 그리고 상추의 곡선은 우리가 갖고 있지 않습니다.
⚠️ 인용할 때 조심할 것 두 가지 ① 분할매수 — 옌센이 말해주는 건 "조화평균 ≤ 산술평균"이라는 사실뿐입니다. 비교 대상인 "평균 주가에 한 번에 사기"는 그 평균을 미리 알 수 없어 실행 불가능한 선택입니다. 실제 대안인 거치식과 비교하면 시장이 우상향하므로 거치식이 더 자주 이깁니다. "분할매수가 최적"이라는 뜻이 아닙니다.

② 소득과 행복 — 개인의 효용이 오목하다는 것까지는 논쟁이 없지만, "사회 전체의 행복 총합"으로 넘어가면 행복을 사람끼리 더할 수 있다(기수적 효용)와 모두의 효용함수가 같다는 가정이 몰래 들어옵니다. 경제학에서 오래 다퉈온 문제입니다. 이는 공리주의적 재분배 논증으로 알려진 것이지 증명된 결론이 아니므로, 수학이 정책적 결론을 보증하는 것처럼 쓰지 마세요. 같은 오목함수를 쓰려면 보험·위험회피 쪽이 안전합니다.

4. 왜 달라지나 — 곡선이 휘어 있으면

가로축은 흙 수분, 세로축은 그때의 생장속도입니다. 시간 그래프가 아닙니다.

⚠️ 아래 그림은 "만약 오목하다면"이라는 가정입니다 오목이 정답이어서가 아니라 설명하기 쉬워서 먼저 그린 것입니다. 숫자(30·80·90)도 임의로 지어낸 예시이지 측정값이 아닙니다.
다음 절에서 곡선을 뒤집어 보면 결론이 정반대가 됩니다. 두 그림을 함께 보세요.
두 점을 잇는 직선(현)이 곡선보다 아래에 있다. 이것이 옌센 부등식의 전부다.
  • 꾸준한 그룹 — 늘 40%에 있으니 곡선 위의 점 하나. 값 = 80
  • 널뛰는 그룹 — 25%일 때 30으로, 55%일 때 90으로 자람 → 평균 60 = 현의 중점

이 그림에서는 25%에서 잃은 것을 55%에서 갚지 못합니다 — 위쪽이 이미 포화라 물을 더 줘도 그만큼 안 늘거든요. 손해는 큰데 보상은 작습니다. 단, 이건 곡선이 이렇게 생겼다고 가정했을 때의 이야기입니다. 상추가 정말 이런지는 아무도 재본 적이 없습니다.

★ 식물이 스스로 계산해서 잎 크기로 답을 내놓습니다 식물은 매 순간 자기가 처한 수분에 맞춰 자랍니다. 6주 뒤의 크기는 순간순간 속도를 다 더한 것입니다. 우리는 그 답을 카메라로 읽을 뿐입니다.
잎 크기의 차이 = 곡선이 얼마나 휘었는지의 측정.

5. 그런데 어느 쪽으로 휘었는지 모릅니다

같은 두 점, 같은 평균. 곡선의 휜 방향만 뒤집으면 결론이 정반대가 된다.
부등식은 수학이라 확인할 게 없습니다 곡선이 오목하면 널뛰는 쪽이 손해라는 건 증명된 정리입니다. 실험이 필요 없습니다.
모르는 건 딱 하나 — 상추의 곡선이 이 구간에서 어느 쪽으로 휘었느냐. 그건 계산으로 알 수 없고 재봐야 압니다.
나온 결과읽는 법확실한가

같다직선 또는 두 효과가 상쇄구분 불가

세 결과 모두 답입니다. "차이가 안 나면 실패"가 아닙니다 — 화분이 6개뿐이라 통계가 약한 상황에서 이건 결정적인 이점입니다.

아래 두 칸의 애매함은 n=3에서 못 풉니다 — 단서는 뿌리뿐 같은 데이터가 두 가지로 읽힙니다. 유일한 단서가 6주차 뿌리 건중량입니다.
널뜀군이 뿌리를 더 뻗었다면 → 경화의 물증. 뿌리가 같은데 더 컸다면 → 곡선이 볼록.

★ 이 곡선은 실험의 결과물이 아닙니다 — 설명 도구입니다 가로축이 수분, 세로축이 생장이라 "수분을 여러 값으로 바꿔가며 생장을 쟀다"처럼 보이지만 우리는 그렇게 하지 않습니다. 그건 화분 6개를 각각 다른 수분에 고정하는 방법 A이고, 반복이 없어 쓸 수 없습니다.

· 꾸준군 → 곡선 위의 점 하나 = f(평균)
· 널뜀군 → 곡선 위의 점이 아님. 구간 전체를 머문 시간으로 가중한 값 = 평균 of f

6. 생물학적으로는 무엇을 기대할 수 있나

수학은 부호를 정해주지 않습니다. 그러면 생존과 번식의 관점에서는 어느 쪽을 예상할 수 있을까요?

★ 진화 자체가 옌센 부등식의 지배를 받습니다 — 복리와 같은 수학 개체수는 세대마다 곱해집니다. 100마리 → 2배 → 0.5배 → 원위치. 복리와 똑같습니다. 곱셈으로 쌓이니 실제로 더해지는 건 로그이고, 로그는 오목합니다.

그래서 자연선택이 최대화하는 것은 산술평균 적응도가 아니라 기하평균 적응도입니다: exp(E[ln W]) ≠ E[W]

즉 적응도의 변동성 자체가 페널티입니다. 그래서 자연은 위험 분산(bet-hedging) 형질을 선택합니다 — 평균 적응도를 낮추더라도 변동을 줄이는 쪽으로. 씨앗이 한꺼번에 발아하지 않고 휴면 기간이 제각각인 것이 바로 이것입니다.

자연에서는 일정한 수분이 오히려 인공입니다

비는 펄스로 옵니다. 자연의 토양수분은 원래 톱니 모양입니다 — 흠뻑 젖었다가 서서히 마르고, 또 젖고. 우리가 만든 "꾸준한 그룹"이야말로 자연에 없는 조건입니다.

그러니 상추는 오랜 세월 널뛰는 수분 속에서 선택되어 왔습니다. 변동에서 심하게 손해 보는 계통은 이미 도태됐을 것이고, 남은 것들은 대비 기제를 갖췄을 겁니다 — 삼투조절, ABA 신호, 뿌리 가소성, 수력 축전.

★ 그런데 대비는 공짜가 아닙니다 뿌리를 더 뻗으려면 탄소를 써야 하고, 기공을 보수적으로 운영하면 광합성을 덜 합니다. 보험료는 생장속도에서 나옵니다.

적응했다 ≠ 손해가 없다. 적응은 변동을 견딜 만하게 만들 뿐 공짜로 만들지 않습니다.

★ 볼록이면 변동 유리, 오목이면 변동 불리 — 진화가 정말 이렇게 작동합니다

"곡선이 볼록이냐 오목이냐가 변동성의 유불리를 정한다"는 직관은 진화생물학의 정립된 이론입니다. 자원→적응도 관계가 가속(∪ 볼록)이면 변동-선호(variance-prone)가, 감속(∩ 오목)이면 변동-회피(variance-averse)가 유리하다는 것이 위험분산(bet-hedging) 이론의 핵심입니다.

★ 그런데 반전 — 두 개의 층이 있습니다 (여기가 핵심) 변동성 유불리에는 서로 다른 두 층이 있고, 섞으면 안 됩니다.

① 개체 수준 (우리 실험이 재는 것) — 수분→생장 곡선의 볼록성. ∩일 수도 ∪일 수도 있어 재봐야 압니다.
② 세대 간 (진화 수준) — 적응도는 세대마다 곱해지므로(번식=곱셈), 진화가 최대화하는 건 산술평균이 아니라 기하평균 적응도 exp(E[ln W])입니다. ln이 오목이라 세대 간 변동은 곡선 모양과 무관하게 거의 항상 적응도를 깎습니다.

즉 개체 수준에서 ∪(변동이 생장에 이득)로 나오더라도, 그것이 번식 적응도에 이득이란 뜻은 아닙니다. 세대 간 곱셈 구조가 변동을 처벌하니까요. 이 때문에 씨앗 휴면 같은 bet-hedging이 진화했습니다.
그래서 이 실험의 정확한 자리 — 야심은 살리되 과잉주장은 피함 우리는 ①개체 수준 곡선의 부호를 측정합니다 (수분→잎생장이 ∩냐 ∪냐). 이 부호는 bet-hedging 이론이 예측하는 변동성-감수성의 한 입력값입니다.

하지만 적응도(씨앗 수) 자체는 재지 않습니다. 그러니 "변동이 생존·번식에 유리/불리"로 직결시키지 않습니다. 포괄적 이론(볼록↔변동선호, 오목↔변동회피)과 우리 측정값을 잇되, 잎생장의 부호가 진화적 유불리라고 주장하지 않는다 — 이 선을 지키면 야심 찬 연결이 정직한 연구가 됩니다.
선행연구가 이미 있습니다 — 아래 별도 절에서 자세히 상추를 포함한 여러 작물에서 "안정 수분이 변동 수분보다 유리"하다는 보고가 있습니다. 이는 우리 H₁(오목 ∩) 방향과 일치합니다. 다만 그들이 무엇을 못 했는지가 우리의 자리입니다 — 절 9 참조.
⚠️ 가장 정직한 한계 — 진화는 우리가 재는 것에 관심이 없습니다 자연선택이 최적화하는 것은 생장속도가 아니라 적응도(씨앗 수)입니다. 우리가 재는 것은 잎 면적이고요. 둘은 같지 않습니다.

변동에 대비해 뿌리에 투자한 상추는 잎이 작지만 살아남습니다. 우리 눈에 "손해"로 보이는 것이 식물에게는 이득일 수 있습니다.

즉 "진화적으로 적응했으니 손해가 없어야 한다"는 추론은 성립하지 않습니다. 이 구분을 보고서에 명시하세요 — 잎 면적은 적응도의 대리지표가 아닙니다.

8. 그래서 시스템이 필수가 됩니다

  • 좁은 밴드 유지는 손으로 불가능 — 사람이 5분마다 흙을 만질 수 없습니다
  • "평균이 같았다"의 증명이 필요 — soil 로그가 없으면 실험이 성립했다는 근거 자체가 없습니다
  • 널뛰는 그룹의 실제 평균은 계산이 아니라 측정 — 다음 패널에서 설명
연구의 착안 주가·전류·소요시간·효용에서 우리는 이미 같은 현상을 봅니다 — 평균이 같아도 흔들림이 결과를 바꾼다. 그리고 그 방향은 오직 곡선의 휨이 정합니다.

그렇다면 자연에서도, 식물의 생장에서도 같은 메커니즘이 관찰될까? 물을 얼마나 주느냐가 아니라 어떻게 흔들리게 주느냐가 생장을 바꾼다면, 상추의 수분–생장 곡선은 어느 쪽으로 휘어 있는 것일까?

이것이 본 연구의 질문입니다. 사람이 만든 시장과 회로에서 성립하는 수학이 살아 있는 것에서도 성립하는지 — 그 답은 계산으로 알 수 없고 재봐야 알 수 있습니다.

9. 선행연구 — 어디까지 왔고, 우리는 무엇을 다르게 하나

이 질문은 이미 연구된 적이 있습니다. 모르고 하면 "재탕", 알고 하면 "빈 곳 채우기"가 됩니다. 정확히 짚고 갑니다.

있는 것 — 상추에서도 "안정 우세"가 반복 보고됨 토양수분의 시간적 변동을 다룬 연구들이 대체로 안정(stable) 수분이 변동(fluctuating)보다 유리하다고 보고합니다. 상추(로메인) 사례가 특히 직접적입니다:

· 로메인 상추 — 안정 수분에서 초장·잎 수·잎 크기·생물량이 유의하게 높음. 게다가 뿌리 크기와 무관하게 그러함 (2025)
· 체리 무 — 비슷한 평균 수분에서 안정이 광합성·기공전도도↑, 스트레스 지표(프롤린·MDA)↓, 생물량↑ (2024)
· 로메인 상추 — 안정(변동계수 CV 5.0%) vs 변동(CV 10.3%)에서 안정이 수분이용효율(WUE) 개선 (2022)

방향은 우리 H₁(오목 ∩, 안정 우세)과 일치합니다.
★ 두 문헌이 따로 존재합니다 — 서로 안 만납니다 A. 상추 "안정 vs 변동" 연구(위) — 결과는 보고하지만 옌센 언급이 없습니다. 농학 지표(WUE·생물량)로만 서술.
B. 옌센을 쓰는 생물학 연구 — 온도 변동이 대사율을 높이고(∪), 빛 변동이 1차생산을 낮추고(∩ — 광합성 포화, 우리와 같은 방향), 먹이 밀도 변동이 포획률을 낮춘다는 식으로 널리 쓰입니다. 최근엔 토양수분+옌센도 나왔는데 대상이 토양 호흡(미생물)이지 식물 생장이 아닙니다.

방법론 선례 — 토양 호흡 연구(2026)가 같은 틀을 씁니다 AmeriFlux 대륙 규모 데이터로 "시간분해 입력 vs 장기평균 입력의 차이 = 옌센 효과"를 정량화한 연구가 있습니다. 건조지에서 중앙값 −63.6% 차이가 났고, 치우친(skewed) 수분 분포일수록 효과가 컸습니다. 대상만 미생물이고, 우리는 같은 틀을 식물 잎생장으로 옮깁니다. "이 방법이 토양과학에서 검증됐다"는 근거가 됩니다.
★ 그런데 — 이것이 "곡선이 오목함을 입증"한 것은 아닙니다 선행연구가 오목 방향의 결과를 보였다고 곡선이 오목임이 입증된 것은 아닙니다. 세 가지 이유:

① 평균이 어긋났을 수 있습니다 — 많은 연구가 변동군을 더 마르게 둡니다. 그러면 "안정 > 변동"이 나와도 (a) 곡선이 오목해서인지 (b) 변동군 평균이 낮아서인지 구분이 안 됩니다. 곡선의 볼록성이 아니라 단순히 물이 부족해서일 수 있습니다.
② 곡선을 그린 게 아닙니다 — 선행연구도 막대 두 개를 비교했을 뿐, RGR(w) 곡선의 모양을 잰 게 아닙니다. 우리 실험이 "부호 하나만 준다"고 한 것과 같은 한계를 그들도 갖습니다.
③ 메커니즘이 다를 수 있습니다 — "안정 우세"가 옌센(곡선 볼록성)이 아니라 침수·건조 손상, 미생물 군집 변화 등 곡선의 휨과 무관한 별도 원인일 수 있습니다.
★ 그래서 우리의 자리 — 선행연구의 약점이 곧 우리의 강점 선행연구가 오목을 시사하지만 입증 못 한 이유가 바로 평균 교락입니다. 그리고 우리 설계의 핵심이 평균 실측 정렬입니다.

선행연구의 약점(평균 교락) = 우리 설계의 강점(5분 로그 + 실측 평균 정렬)

즉 우리는 "안정이 유리하다"를 재확인하는 게 아니라, 그게 정말 곡선의 오목함(옌센) 때문인지, 아니면 그냥 물 부족 때문인지를 분리합니다. 선행연구가 못 한 바로 그 지점입니다.

널뜀 < 꾸준 (선행과 일치)이 구간 오목 ∩ 확인 — 게다가 평균을 맞췄으므로 물 부족이 아닌 진짜 변동성 효과
널뜀 ≈ 꾸준선행연구의 차이가 평균 교락 탓이었을 가능성 — 의미 있는 반증

10. 용어 — 오목/볼록은 항상 기호와 함께

한국 교과서 "위로 볼록"이 혼동을 만듭니다 말은 "볼록"인데 수학 용어로는 오목(concave)입니다. 늘 ∩/∪ 기호를 병기하세요.
그래프교과서수학 용어최고차항변동성이
∩ (언덕)위로 볼록오목 concave음수손해 (안정 우세)
∪ (그릇)아래로 볼록볼록 convex양수이득 (변동 우세)
외우는 법: 물을 담을 수 있으면 볼록(∪), 흘러내리면 오목(∩). 영어 concave = 동굴(cave) 천장이 ∩로 파임 → 오목.
우리 실험과 물리의 대비 저항 발열 P=I²R은 ∪ 볼록 — 그래서 변동(RMS)이 평균보다 큽니다.
광합성–수분 곡선은 위에서 포화하며 꺾이는 ∩ 오목일 것으로 선행연구가 시사 — 그래서 변동이 손해입니다. 같은 옌센, 부호만 반대.

/* 조금 붓고 -> 기다리고 -> 재기를 반복. 더 안 오르면 = 포화.
 * ★ '연속 공급'이 아니라 '버스트 + 대기'인 이유:
 *   센서는 화분의 한 지점에만 있어 물이 도달하는 데 몇 분 걸립니다.
 *   연속으로 부으면 그동안 값이 안 움직여 '평탄하다'고 오판하거나,
 *   타임아웃을 길게 잡으면 그동안 계속 부어 넘칩니다.
 */
#include <M5Unified.h>
const int  PIN_PUMP = 9;                  // 실측 확정: PUMP_EN = G9
const int  PIN_SOIL = 8;                  // 실측 확정: Analog = G8
const int  SOIL_DRY = 3200, SOIL_WET = 1400;   // ★ DRY/WET 보정값으로 교체

const float         EPS       = 1.0;      // %p — 센서 잡음의 3배 이상
const unsigned long BURST_MS  = 2000;
const unsigned long WAIT_MS   = 300000;   // 5분 — 물이 센서까지 도달할 시간
const int           MAX_BURST = 30;       // 안전 상한

float soilPct(int raw) {
  float v = 100.0f * (SOIL_DRY - raw) / (float)(SOIL_DRY - SOIL_WET);
  return v < 0 ? 0 : (v > 100 ? 100 : v);
}

void setup() {
  auto cfg = M5.config(); M5.begin(cfg);
  pinMode(PIN_PUMP, OUTPUT); digitalWrite(PIN_PUMP, LOW);
  Serial.begin(115200);
  analogReadResolution(12);

  float before = soilPct(analogRead(PIN_SOIL));
  for (int i = 1; i <= MAX_BURST; i++) {
    digitalWrite(PIN_PUMP, HIGH); delay(BURST_MS);
    digitalWrite(PIN_PUMP, LOW);
    delay(WAIT_MS);                                  // ★ 도달 대기 — 없으면 오판
    float after = soilPct(analogRead(PIN_SOIL));
    Serial.printf("burst %2d : %.1f -> %.1f  (+%.1f)\n", i, before, after, after-before);
    if (after - before < EPS) {
      Serial.printf("\n>> 포화 = %.1f%%   => 상한(OFF_AT) = %.1f%%\n", after, after - 15.0);
      break;
    }
    before = after;
  }
}
void loop() {}
MAX_BURST를 넘도록 안 멈추면 물이 밑으로 다 빠지고 있거나(구멍이 큼 / 흙이 너무 성김), 튜브가 빠진 것입니다.

왜 Camera Module 3 Standard인가 — Wide·NoIR 아님

변형왜 안 되나
Wide (120°)광각 = 배럴 왜곡 → 6칸 위치 무관성 검사(<5%)를 통과하지 못할 가능성. "낮게 달 수 있으니 광각이 낫다"는 이 프로젝트에선 역방향
NoIRIR 차단 필터 없음 → 엽록소가 근적외선을 강하게 반사 → 채널이 오염되어 ExG가 무너짐

Standard를 고르는 진짜 이유는 화질이 아니라 수급 안정성입니다 — 최소 2030년 1월까지 생산이 보장되어, 6주 실험 중간에 죽어도 동일 모델을 즉시 재구매해 같은 설정으로 복구할 수 있습니다.

왜 "잎 면적"이 아니라 "투영 캐노피 면적"인가

위에서 찍으면 겹친 잎은 한 장으로 셉니다. 실제 잎 면적보다 항상 작게 나옵니다. 성장 추세를 보는 데는 문제없지만(계속 늘어나므로), "잎 면적을 쟀다"고 말하면 틀린 말입니다. 6주차 파괴 측정으로 실제 면적·건중량과의 관계식을 구하면 그때 대리지표로서의 지위가 생깁니다.

왜 원면적이 아니라 RGR인가

"어제보다 몇 cm² 늘었나"로 비교하면 원래 컸던 개체가 항상 이깁니다 — 큰 잎이 더 많은 빛을 받으니까요. RGR = (ln A₂ − ln A₁)/Δt는 "자기 크기 대비 몇 % 자랐나"이므로 개체·시점을 공정하게 비교합니다. 편의가 아니라 식물생리학의 표준 지표입니다.

왜 lux인가 — 그리고 그 한계

lux는 사람 눈의 민감도로 가중된 단위입니다. 사람 눈은 초록에 가장 민감하지만 식물은 초록을 반사하고 빨강·파랑을 씁니다.

이 프로젝트에서 lux를 써도 되는 근거 모든 화분이 같은 LED를 씁니다. 광원이 하나면 스펙트럼이 고정이므로 lux와 PAR의 비율도 고정 → "같았는지 확인"이라는 용도에는 충분합니다.
하지만 "광량이 성장에 미치는 영향"을 연구하려면 lux로는 불가능하고 PAR/PPFD 양자센서가 필요합니다. 보고서에 이 한계를 명시하세요.

왜 UTC로 저장하나

DB에는 UTC, 표시할 때만 +9시간. 노드가 여러 대여도 시각 기준이 하나여서 조인이 정확하고 서머타임 문제가 없습니다. 단, 나중에 systemd 타이머(촬영 예약)만은 로컬시각을 쓰므로 timedatectl set-timezone Asia/Seoul이 필요합니다.

규칙 기반 제어가 "데이터 기반"보다 낮은 단계인가

아닙니다. 우열이 아니라 순서입니다. 규칙 기반 제어(수분 밴드 유지)가 통제 장치 역할을 해야 다른 변수가 일정해지고, 그래야 데이터 기반 분석이 의미를 갖습니다. 게다가 규칙 기반은 생리학적 근거가 있어 데이터가 적어도 견고합니다.

★ 왜 "가장 큰 영향 요인"을 데이터에서 못 뽑나

이 프로젝트에서 가장 중요한 개념 모든 식물을 같은 환경에 두고 관측 데이터를 모으면 환경 변수들이 낮/밤과 함께 다 같이 움직입니다. 빛이 세지면 온도도 오르고 습도도 떨어지고 CO₂도 소비됩니다. 이 데이터에 상관분석이나 머신러닝 변수 중요도를 돌리면 그럴듯하지만 틀린 "1등 요인"이 나옵니다 — 서로 얽혀 있어(교락) 분리가 수학적으로 불가능하기 때문입니다.

요인의 영향력을 알려면 한 요인만 바꾸고 나머지를 붙잡아 두는 실험을 해야 합니다. 그래서 이 프로젝트는 물 하나만 조작합니다. "관측 데이터를 많이 모아 AI로 분석하면 답이 나온다"는 흔한 기대는 실험 설계 없이는 성립하지 않습니다.

센서 데이터의 1차 용도는 그래프가 아니라 통제의 증명입니다

"B가 덜 자랐다"는 결과가 나와도, 알고 보니 B 자리가 더 어두웠다면 그건 물의 효과가 아닙니다. 그래서 분석은 반드시 ① 통제 확인 → ② 처리 확인 → ③ 기준선 → ④ 결과 순서입니다. 환경 노드는 예쁜 그래프를 그리려고 있는 게 아닙니다.

열화상 — 왜 "섹터 평균"을 그냥 내면 안 되나

가짜 결과가 나옵니다 RGB는 섹터 안에서 색으로 잎을 골라낼 수 있지만, 열화상은 못 합니다 — 잎도 흙도 그냥 온도입니다.
섹터 평균 T = (잎 비율 × T_잎) + (흙 비율 × T_흙)
잎은 증산으로 흙보다 차가우므로, 덜 자란 쪽은 캐노피가 작아 잎 비율이 낮고 → 섹터 평균이 높게 나옵니다. 즉 "덜 자란 쪽의 ΔT가 높다"가 기공과 무관하게 순전히 캐노피 크기 때문에 나옵니다. 가설과 딱 맞는 예쁜 그래프인데 완전히 틀린 겁니다.

→ 반드시 RGB 잎 마스크 ∩ 섹터로 잎 화소만 평균하고, 혼합화소를 버리려 마스크를 1~2화소 침식하세요.

MLX90640은 32×24 = 768화소, 화분당 약 128화소입니다. 나오는 것은 잎의 온도 지도가 아니라 화분별 대표 온도 1개 — ΔT에는 충분하고, 실효 데이터는 4~6주차입니다.

공기 온도 대신 기준면 — CWSI ΔT = T_잎 − T_공기 는 T_공기가 ±0.2°C여야 하는데 SCD4x는 자체 발열로 1~3°C 높습니다. 해법은 정밀 온도계가 아니라 화면 안에 기준면을 같이 넣는 것입니다:
CWSI = (T_잎 − T_습윤) / (T_건조 − T_습윤) → 공기 온도가 식에서 사라집니다. 복사·풍속·VPD 변동도 세 면에 똑같이 걸려 상쇄됩니다. 기준면은 여분 상추 잎 2장으로 — 습윤은 물 분무, 건조는 바셀린 도포(기공만 막고 광학 특성 유지). 1주차 솎아내기에서 버리는 개체가 있으니 재료는 공짜입니다.
